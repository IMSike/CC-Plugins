# ADR 0009 — Clickable paths in herdr: dx makes the links, a herdr plugin opens them

- **Status**: accepted
- **Date**: 2026-11-25

## Context

Claude's replies name files and folders all the time (`src/app.ts:12`, inline code), and in Claude Code's terminal a bare path opens nothing. The function-hook API lets a plugin rewrite the text the engine draws for a reply (`ui.render` on `AssistantMessage`, the stored message untouched); the engine draws a Markdown link as a terminal hyperlink (OSC 8) where it believes the terminal shows them, and otherwise writes the URL after the text. It decides as observed in Claude Code 2.1.330 (not documented): `FORCE_HYPERLINK` first (empty, it counts as unset; `0`, `false`, `no` or `off`, spaces and case aside, or a number read as 0, turns them off; any other value on); else Windows Terminal outside tmux (`WT_SESSION`), a `TERM_PROGRAM` of its list (`ghostty`, `Hyper`, `kitty`, `alacritty`, `iTerm.app`, `iTerm2`, `rex`, `WarpTerminal`), JetBrains' terminal (`TERMINAL_EMULATOR=JetBrains-JediTerm`), tmux 3.4 or later (`TERM_PROGRAM_VERSION`), an `LC_TERMINAL` of the same list, a `TERM` holding `kitty`. herdr, a terminal multiplexer, is not known: `FORCE_HYPERLINK=1` in the `env` of Claude Code's settings turns them on.

The API opens no file in another program.

herdr (0.9.5 and later) routes a ctrl+click on a URL to a plugin action when a `[[link_handlers]]` pattern of that plugin matches it and mouse capture is on; the action gets the URL (`HERDR_PLUGIN_CLICKED_URL`) and the pane (`HERDR_PANE_ID`). Without a matching handler herdr opens only http(s) links. A live test (herdr 0.9.5, Claude Code 2.1.330 fullscreen, Windows Terminal with `experimental.detectURLs` off) showed a link `[text](dx-open:…)` drawn blue with its text alone, hovered across wrapped rows, and a ctrl+click on any of its rows running the handler's action in about 0.2 s, with no console window.

The hard rules allow no runtime dependency outside Claude Code; only a tool the system ships may be run through `$.process.run`, when the API offers no other way, with an ADR saying why ([ADR 0003](0003-system-process-list.md)). herdr is no such tool: the API cannot tell which herdr plugins are installed, and only herdr can.

Options studied:

| Option | Pros | Cons |
|---|---|---|
| Nothing: paths stay text | Nothing to run | Copying a path to open it |
| `file:` links in the engine's drawing, opened by the terminal | Nothing to run | What opens is the terminal's choice (ShellExecute in Windows Terminal: a runnable file runs); in herdr, herdr-explorer's preview alone |
| Replies drawn by dx, a plain click answered by dx | One click, no terminal involved | The engine's look imitated; a process per click run by dx; runnable checks spread across dx; Windows Terminal still in the way |
| **`dx-open:` links in the engine's drawing, opened by a herdr plugin** | The engine's own look; dx runs nothing to open a path; the opening, the user's choice and the protection in one place, in Rust, tested | herdr only; ctrl+click; a second plugin to install; `FORCE_HYPERLINK` and Windows Terminal's setting to set by hand |

## Decision

On Windows, inside herdr (`HERDR_PANE_ID` set), when the herdr plugin `imsike.links` of [Herdr-Plugins](https://github.com/IMSike/Herdr-Plugins) is installed and Claude Code shows hyperlinks, dx rewrites the paths of Claude's replies, in the text the engine draws, into links `[as written](dx-open:///C:/…/file#L12-L14)`:

- **one rule says what a path is, and a word is a path whole or not at all.** The plain text of a reply is cut into words at its spaces, as CommonMark reads them (a no-break space is one, a zero-width one is not); a word glued to code, a link or raw HTML is no path. The signs around a word that are not the path's are left out: before it, `(`, `"`, `'` or `<`; after it, `.`, `,`, `;`, `:`, `!`, `?`, `"`, `'`, `>`, and a `)` that closes none the word opened (a period after a separator too, `docs/.`, not two, `../..`); at the word's edges, a run of `*` or `_` as long on both sides, or `~~` on both (`**a.ts**`, `~~a.ts~~`: Claude Code strikes through with two tildes alone, and draws a single one as written), never past an opening sign nor of two kinds (`"*a.ts*"`, `(**a.ts**)`, `*_a.ts_*`: next to the link, an inner mark could pair with one outside the word). What remains is a path when it starts with a drive (`C:\`, `C:/`), the home (`~/`), one of the variables `USERPROFILE`, `LOCALAPPDATA`, `APPDATA`, `TEMP`, `TMP`, `ProgramFiles`, `ProgramFiles(x86)`, `ProgramData`, `SystemRoot`, `windir`, `PUBLIC` (`%TEMP%\`, any case, linked where it leads), a drive as Git Bash or WSL writes it (`/c/`, `/mnt/c/`), or is relative; and when it holds only letters of any script and their combining marks, decimal digits of any script (not `²` nor `½`), `. _ - + ~ @ ( ) '` and the separators, as many `(` as `)`, no two separators in a row (the root's included: `/c//x`), no `..` above an absolute path's start (`/c/../d`), no name of dots alone past two (`src/...`), no trailing backslash, no short 8.3 name (`PROGRA~1`), no name ending with a period or a space, no default-ignorable code point, and, in plain text, no backslash before ASCII punctuation (a Markdown escape: `src\_a.ts` is drawn `src_a.ts`). It must look like a path: a separator, or a name of four signs at least, not starting with a dot, with an extension starting with a letter (`README.md`; not `1.2`, `a.h`, nor `.env` alone). Any other sign (`&`, `#`, `^`, `$`, `%`, `,`, `=`, `!`…) or any other root (`/tmp`, `\x`, `\\server`) makes the word no path: no part of it is ever read as one. A word therefore has one reading, checked once on disk;
- **a path holding spaces is linked only where it is delimited**: in inline code and between double quotes in plain text (`"C:\mes notes\a.txt"`). Written bare, it is several words, and none of them is linked where it can be told: of two words only spaces apart, the second not absolute, neither is linked when the other holds a sign a name holds besides letters and digits (`C:\mes notes\a.txt`, `fichier (1).txt`, `a - copie.md`). A word ending with signs left out, or a line ending, ends the path (`src/a.ts, src/b.ts` is a list, and so are paths one per line). A word between whitespace that Claude Code makes a link of in plain text, holding `://` or `www.` anywhere, or an email address (`a@b.com`), holds no path, nor does anything glued to it, inline code included: Claude Code extends such a URL over all that is glued after it;
- the paths are also read in inline code, as written (no escapes there; one space dropped on each side when both hold one, as CommonMark does); `file:` URLs, percent-encoding and character references are not read. A line or a range goes with the link: `:12`, `:12-14` or `:12:5` (the column dropped) after a path in text or code. The reply's Markdown is read as CommonMark 0.31.2 reads it (`markdown.ts`): code of every form, raw HTML, autolinks, links (their text and their target), images and reference definitions are left as written. Claude Code reads replies with its own lexer, built on marked with many of its rules replaced; dx models CommonMark 0.31.2, with GFM's strikethrough and autolinks, as an approximation of it, checked against Claude Code 2.1.332's lexer on real replies and on random ones, the differences left listed under Consequences;
- a path is linked only if it exists (`$.fs.stat`, cached 5 minutes, 10 s when absent; a drawing waits 0.3 s at most for its checks, a late one waited for by no later drawing, and having the replies drawn again as it answers; a check unanswered never asked again before it answers, as a dead drive may never answer), if, as written once a variable is placed and where it lands (`realPath`), herdr's plugin takes it (a drive, shorter than 260 UTF-16 units, no device name such as `con.txt`) and dx's own stricter rule does too (names of the signs above or spaces alone, none ending with a period or a space: herdr refuses fewer: `/ \ : * ? " < > | , ; %`, control, invisible and private-use characters, noncharacters), if it is not too broad as text or code (a drive's root, the working directory, the home), and if it is not one of Claude Code's own settings files, as written or where it lands (`realPath`; a path whose landing the engine does not say is not linked), nor one in the folder where Claude Code's configuration folder lands. At most 256 distinct paths a reply, and no link whose URL would pass 2,048 characters; none in a reply past 100,000 characters or 1,000 lines, which Claude Code draws without hyperlinks (as read in Claude Code 2.1.330, not documented);
- a link dx makes changes nothing else CommonMark reads of the reply: after an unescaped `!` it escapes it; a path holding a `_` or `~~` that may pair with another, as CommonMark's flanking rules tell, is not linked, in quotes too: drawn as emphasis, it is not what is written (`__init__.py`, `src/_a_.ts`), and a link would break the emphasis (`_voir le src/a.ts_`, `_voir "src/b_"`); nothing is linked where a link would make another reference (`[ref][src/a.ts]`). The URL carries the path and the lines alone: `dx-open:///` then the drive and each segment percent-encoded as UTF-8 (parentheses, `!`, `'` and `*` included), then `#L12` or `#L12-L14`. What a click does, and whether a runnable file may ever be launched, is the herdr plugin's setting, never read from the URL; that plugin checks the real target again at click time ([Herdr-Plugins ADR 0012](https://github.com/IMSike/Herdr-Plugins/blob/main/docs/en/adr/0012-link-dispatch.md)).

The grammar is deliberately narrow: a path read as far as the text allows (past its spaces, with or without emphasis marks), the longest reading that exists linked, would let a sign glued to a path make one of its readings another file's name. A whole word read once leaves no shorter reading to go wrong. It is held to a judge, `paths-oracle.test.tsx`: random replies whose tokens' meaning is known, a disk holding the path meant and decoys (every part of a token cut at a sign), every link checked to lead to a path its token means, and a fifth at least of the paths meant linked; the audits' findings stay in it as fixed cases.

dx runs one process as the session starts, inside herdr alone: `herdr plugin list --plugin imsike.links --json`, herdr's read-only listing (herdr by the path herdr gives its panes in `HERDR_BIN_PATH` when that is an absolute path with a drive, else `herdr` by its name, found on the `PATH`; run from the system folder (`SystemRoot`, else `windir`) so that no `herdr.exe` of the working directory runs in its place, and not run at all when neither is set; 10 s at most, asked again when it fails or is late, after pauses of 5 s, 30 s, 1 min and 2 min, each drawn within 10 % either way so that the sessions herdr restores together do not ask together), not awaited by the session's start. herdr is the third-party tool, detected at run time, whose absence changes nothing: rule 5 of [AGENTS.md](../../../AGENTS.md) and the contributing guide admit such a tool from this ADR on, each new use with an ADR of its own. The plugin listed, enabled and holding its `dx-open` handler turns the links on; anything else leaves the replies as the engine draws them, so that no link leads nowhere.

The settings pane's **Fonctions** tab shows, inside herdr only, a **Chemins** section: **Chemins cliquables** (on by default), and a line saying what is missing: the herdr plugin, herdr not answering, the system folder unknown, or `FORCE_HYPERLINK=1` (said apart when `FORCE_HYPERLINK` is set to turn hyperlinks off).

## Consequences

- dx starts nothing to open a path and holds no list of runnable types: the herdr plugin is the only place that opens, and refuses.
- What the narrow grammar leaves unlinked, by design: a path holding spaces written bare; a path glued to a sign outside the list (`src/a.ts#L5`, `100%.txt`, `Q&A/x.md`), or next to a word holding one of a name's signs (`src/a.ts (1.2)`); a path from a root (`/tmp/x`, `/etc/hosts`); Git Bash's other mounts; a path holding `www.` (`docs/www.readme.md`, a web address to Claude Code); a path in a link the model writes. A word of letters alone next to a path is taken as prose: `C:\Program Files` written bare links `C:\Program` when that exists, and `C:\x\mes vieilles notes\a.txt` links `C:\x\mes` and `notes\a.txt`, relative to the working directory, when they exist.
- Where Claude Code's lexer reads a reply otherwise than dx's model, in rare replies:
  - Claude Code draws every link of the reply as `text (address)`, and a linked path shows as `src/a.ts (dx-open:///C:/…)`, when an inline HTML tag is left unclosed earlier in the reply (`<code>`, `<kbd>`, `<pre>`, `<script>`, `<a …>`), when the reply holds a `\r` (CRLF line endings), or when it ends with exactly one space after a list item, a task item or a setext underline, with no final line feed.
  - A reply holding no Markdown sign is drawn as is, without being parsed; once dx adds a link it is parsed, so `a\.b` shows as `a.b` and `1.<tab>foo` becomes a list. The path stays clickable.
  - A path after a tab following a list or quote marker (`1. <tab>src/a.ts`) is indented code to Claude Code: the link shows raw.
  - A `~` right before backticks (`` ~`src/a.ts` ``) makes Claude Code read them as text, not as a code span: a path linked there shows without its backticks, or its link raw.
- Outside herdr, off Windows, without the plugin or without hyperlinks, replies are drawn untouched; the cost is a few environment reads, and inside herdr one process per session (up to five while herdr fails or is late).
- The plugin installed during a session takes effect at the next session.
- The look of the replies is the engine's own; the stored message, and what the model reads back, are unchanged.
- `FORCE_HYPERLINK=1` is the user's to set (dx does not set it: every program the session starts would inherit it); Windows Terminal's `experimental.detectURLs` off and herdr's mouse capture on are documented, not checked.
- A model, or a program in another pane, printing a `dx-open:` link can only make the plugin do what a real link does with the user's own setting; dx leaves such a link of the model's as written, and the herdr plugin is the guard.
- dx leaves the `file:` URLs the model writes as they are: with Windows Terminal's `experimental.detectURLs` off and herdr capturing the mouse, nothing hands them to Windows, and outside herdr what a terminal does with them is its own behaviour, not dx's. Turning Windows Terminal's URL detection back on brings that risk back: a ctrl+click on such a URL may then run a program.
- Claude Code's own settings files stay unlinked: Claude Code refuses a plugin to name them to a program, and dx does not work around that through another program; the settings pane's `[ 📁 dossier .claude ]` button opens their folder ([ADR 0007](0007-configuration-folder.md)).
- Settings shape `settings-14`: one boolean added; a new state key `paths` (shape `paths-1`), what the settings pane says of the requirements.
- To be reassessed if the API opens files itself, if Claude Code documents or changes its hyperlink rule, or if herdr changes its link handlers.
