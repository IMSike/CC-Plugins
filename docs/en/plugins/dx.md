# dx — developer experience

**English** · [Français](../../fr/plugins/dx.md)

Install: `/plugin install dx@cc-plugins` (after `/plugin marketplace add IMSike/CC-Plugins`). Requires Claude Code 2.1.310 or later.

If one of dx's parts (settings, notes, activity, band) fails to start, at the session's start or a turn's, the others start all the same, and the debug log (`claude --debug-file <file>`) has a `dx : démarrage échoué, … (…)` line naming it, with the reason in parentheses.

## Status band

```text
╭─ ✻ Opus 5.5 ─ ▰▰▰▰▱ xhigh ────────── ~/repo/app ⎇ dev ─ ✎  ⚙  ─╮
│ ctx  22% ◎◎◎◎◎◎◎◎◎◎···································         │
│ 5h   12% ◎◎◎◎◎◉◉◉◉◉◉◉◉◉·······························  ↻ 3h24 │
│ 7j   71% ◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◉◉◉◉◉◉◉◉◉◉◉◉············· ↻ 1j15h │
╰─ ✻  ✻  ▣  ▣  ─ durée 1m04 · fin 14:32 · total 1h12 · 24k/200k ─╯
```

On screen, colors tell apart what plain text cannot: on `5h`, the `◉` are the pale budget; on `7j`, they are consumed ahead of the pace, in full color. In the bottom border, `▣` stands for the terminal icon, a Nerd Font glyph; in the top border, `✎` and `⚙` stand for the notes and settings icons, two more (nf-fa-edit and nf-oct-gear by default).

- **Effect**: an instrument panel directly above the prompt, framed and laid out in the terminal's width.
  - **Top border**: the spark `✻`, lit in Claude's color while Claude works and grey at rest; the model (`claude-opus-5-5` reads `Opus 5.5`; a model id ending in `[1m]`, for the 1M context window, adds `(1M)`); the reasoning effort as a five-step meter (`low` ▰▱▱▱▱ to `max` ▰▰▰▰▰) and its name; the current directory, the home folder shown as `~`, cut from the left when space runs out; the Git branch after `⎇` (a short commit when detached); at the right end, `✎` and `⚙` open the notes and settings panes (below).
  - **Gauges**: `ctx`, share of the context window used by the last request; `5h` and `7j` (`7d` if so set, below), share of the 5-hour and 7-day usage limits used. Each gauge is a string of beads: double circles `◎` for what is consumed, on a track of small dots `·`, drawn in a **heat gradient**: every cell takes the color of its position, green, yellow, orange, then red, each color blending into the next and halfway between them at 25%, 50% and 75%, so a gauge reddens as it lengthens. The percentage takes the color its value reaches.
  - **Pace** on `5h` and `7j`: the pace is where a steady consumption would stand at this point of the window (the share of the window already gone). The gap between it and the consumption is drawn in dotted circles `◉`. Behind the consumption, pale `◉` follow it: the budget, what can still be used without running ahead. Ahead of it, the consumed beads past the pace turn into `◉` in full color: usage is faster than the window allows on average, by that many beads.
  - **Shuttle**: a glow, fading out over the beads behind it, glides along the consumed beads from the first to the last, easing in and out, in 0.4 s plus 22 ms per bead (2.6 s at most: a short gauge is a quick course), then rests 3.5 s. The gauges' shuttles leave 1.4 s apart, then each keeps its own rhythm (its course depends on its length), so they may overlap; a gauge with fewer than 6 consumed beads has none. It moves by fractions of a bead, its light shared between two neighbours. It is drawn by the terminal itself (a `Client` element and its frame clock): the band is not recomputed for it, and nothing moves while it rests.
  - **Countdown**: `↻ 3h24`, time left before the window resets. When the window will run out before then at the rate it has been used since it started, the countdown gives way to `⚠ 1h10` in red: the time left before it runs out (no forecast during the first 2% of the window).
  - **Frame**: yellow. Two glints go round it, half a lap apart, a lap every 18 s, each a brighter stretch of the line, fading in over 4 cells ahead of it and out over 10 cells behind it; like the shuttle, they are drawn by the terminal itself.
  - **Bottom border**: on the left, what runs beside the conversation (below); on the right, the last turn's duration (`durée`, counting while Claude works) and the time it ended (`fin`), the session's total duration (`total`), and context tokens over the window size.
- **Data**: read from Claude Code itself (`$.session.usage()`, `$.session.model()`, the `effortLevel` setting, the effort each request is really sent with), the main loop's turns (`turn.start`, `turn.complete`), and the repository's `HEAD` (read only): a `.git` looked for in the session's folder, then in each parent up to the root (a `.git` folder without a `HEAD` is passed over, as Git does), and its `.git/HEAD` read, or for a worktree or a submodule the `HEAD` its `.git` file points to; nothing is sent anywhere. Refreshed at the end of each turn and every 30 seconds, a refresh that fails keeping the last figures (when refreshes start failing, the debug log, `claude --debug-file <file>`, has a `dx : bandeau non rafraîchi` line); the turn's duration every second while it runs.
- **Implications**:
  - The `5h` and `7j` lines only appear with a Claude subscription (the API reports no limits otherwise); `ctx` shows `—` until the first response, and after a compaction until the next one.
  - `total` counts from the session's start, for a resumed session from its first launch; a `/clear` starts it over.
  - The band takes up to five rows: one per gauge shown, and its two borders. It is drawn in the terminal and the desktop app; other surfaces (VS Code, mobile) do not show it.
  - The repository is located once per directory, its `HEAD` read again on each refresh: a branch switch shows, and a `HEAD` or a worktree's `.git` file Git is rewriting at that moment, or a lookup refused for a moment (a guard), only hides the branch until the next refresh. A repository on a network location never shows its branch: Claude Code's file access does not reach network locations. A `.git` file that names no repository, or a removed worktree's, shows no branch, and a repository created after the session started (`git init`) does not show its branch either, until the next session or a reload.
  - It is not the status line: it sits **above** the prompt, and a `statusLine` configured in `settings.json` keeps being shown under it. Remove `statusLine` to avoid seeing the same figures twice.
  - The frame, the gauges, the effort meter and the branch use characters (`╭ ◎ ◉ ▰ ⎇`) present in common terminal fonts (Cascadia, Nerd Fonts); the robot and terminal icons, and the default notes, settings and monitor icons, need a [Nerd Font](https://www.nerdfonts.com).
  - While Claude Code shows a survey in that band, the survey takes its place.
- **Fold / unfold**: `ctrl+x ctrl+a`, or click `[-]`.

## Subagents and background tasks

The left of the bottom border holds an icon for each subagent and background task of the session, up to five of a kind (as set, below), then a count (`+3`). Working and waiting subagents are two kinds, each capped on its own: up to ten subagent icons by default. Agent CLIs for Claude Code, agent CLIs for Cursor, shells and monitors are a kind each.

- **Effect**:
  - **Subagent**: `✻` in Claude's color, turning like Claude Code's own spinner (`· ✢ * ✶ ✻ ✽`, there and back, 200 ms a step) while it works, still and dim while it waits.
  - **Agent CLI** run in a background shell: a robot, in Claude's color for Claude Code, grey for Cursor.
  - **Background shell** (`run_in_background`): a terminal icon, grey; a `Monitor`: a pulse (nf-oct-pulse), grey, or the glyph chosen in the settings.
  - **Click a subagent**: its transcript takes the main view, as from the tasks list; its icon is underlined meanwhile. Click it again to come back to the main conversation. Should Claude Code refuse the switch, a toast says `dx : ` followed by its reason.
  - **Click a shell, an agent CLI or a monitor**: the side panel shows its command, whole, wrapped over as many lines as it needs, then the end of its output (as much of its last 200 lines as fits), read again every second: **Pas encore de sortie.** while there is none, **Fichier de sortie introuvable.** when dx does not know where it is written, **(sortie illisible)** when it cannot be read. Its tab atop the panel reads the command's first line, cut at 24 characters. Click the icon again to close the side panel.
  - An icon leaves the border when its subagent finishes, or its task is stopped or ends.
- **Data**: the session's agents (`$.agent.list()`); the background tasks, from the tool calls that start and stop them and from Claude Code's notification rows; their output, read from the file Claude Code writes it to. To tell an agent CLI in a shell and to catch an end Claude Code did not report, dx reads the system's process list ([ADR 0003](../adr/0003-system-process-list.md)): PowerShell on Windows, `ps` through `sh -c` elsewhere, only while a task is due for a check (2 s after it starts, then after 10 s, 1 min, 5 min, then every 15 min). It keeps only the shells' ids and whether an agent CLI runs under them; nothing is sent anywhere.
- **Implications**:
  - On Windows, a check costs about 0.3 s of CPU on one core and 80 MB of memory for its duration, in the background; with no background task, nothing is read. Should the read fail, the icons follow Claude Code's signals alone.
  - A shell is recognised by the words of its command: two background shells running the same command can each be matched to the other's process, the agent CLI or the end it reveals then being the other one's; the output shown stays right.
  - While the spinner is on and a working subagent's icon is shown, the band is redrawn on each spinner step; while a turn runs, every second.
  - Unchecking **Sous-agents et tâches** in the settings only hides the icons: dx still follows the tasks and reads the process list as above, and each task's terminal stays among the panel's tabs.
  - Reloading the plugin forgets the tasks under way: only the tasks started afterwards get an icon.

## Settings

The `⚙` icon shows the settings in the side panel; a second click closes it. A change applies at once and is kept across sessions.

- **Effect**:
  - **Display**: each element of the band on or off: model, effort, directory, Git branch, each gauge, countdowns, subagents and tasks; the 7-day gauge's label (**Libellé de la jauge 7 j**), `7j` (French, by default) or `7d`, which also sets the day unit of the durations the band shows, its countdowns, the red `⚠` forecast and the session's total: `1j15h` with `7j`, `1d15h` with `7d`.
  - **Bottom border**: the turn's duration, its end time, the session's total and context tokens, each on or off and moved up or down with `↑` `↓`; how many subagent icons, and how many task icons (agent CLIs, shells, monitors), of a kind before a `+N` count (5 each by default, 1 to 10).
  - **Animations**: the frame's glints, the gauges' shuttle, the subagents' spinner, each on (by default) or off; the speed of the glints and the shuttle (slow, half as fast; normal, by default; fast, twice as fast). The spinner keeps Claude Code's pace whatever the speed.
  - **Colors**, each picked from a list of named colors or typed as hex (`#58a6ff`): the frame (the theme's warning color, yellow, by default), the effort meter and the branch (Claude's color by default), the gauges (the heat gradient by default, or one color), the bottom border's text (dim by default). The band shows a change at once.
  - **Gauge thresholds**: where the heat gradient turns orange (50% by default, from 10% to 90%) and red (75% by default, from 5 points above orange to 95%), by steps of 5; yellow sits halfway to orange.
  - **Icons**: the glyphs of the notes and settings icons (nf-fa-edit and nf-oct-gear by default), and of a monitor's (nf-oct-pulse by default; also an eye, a radar, a broadcast, a bell), among a few Unicode and Nerd Font ones; one the terminal's font lacks draws as a blank or a box.
  - **Notes**: the tab the pane opens on (**Global** by default); whether it takes up the last tab shown instead (on by default); how many other sessions' notes are listed at a time (8 by default, 0 to 20); at 0 the list disappears, and other sessions' notes can no longer be opened or deleted from the pane.
  - **Behavior**: hide the `5h` gauge while its window has not started (on by default); off, its row is drawn empty. Animate only while Claude works (off by default): the glints and the shuttles rest otherwise; with **… ou qu'un sous-agent ou un shell est actif** (checked along with it by default), they also run while a subagent works or a background task runs. The subagents' spinner turns only while its subagent works in any case.
  - **Réinitialiser** puts every setting back to its default.
- **Data**: kept in dx's own store, a JSON file under Claude Code's configuration directory (`~/.claude` by default; observed in its `plugins/store/` folder) ([ADR 0004](../adr/0004-settings-and-notes.md)). A change Claude Code fails to save still applies to the current session, and the pane says so in red under its tabs, **⚠ réglages non enregistrés : …** followed by Claude Code's message, until a later change saves. Until then, the next changes build on the current session's settings rather than on the store, so the save that succeeds writes them all (and replaces any change another session saved meanwhile), and the `⚙` icon, rather than reading the settings again from the store, tries to save them again: once Claude Code saves them, the warning goes. A `/clear` keeps such a change and its warning: should Claude Code empty dx's state, dx remembers them in memory, within the Claude Code process that ran the `/clear`; the pane shows them at once, the band from the next prompt. A read of the store that fails leaves the settings shown as they are; should the store never have been read since the session started, a change is not applied (they would be the defaults, written over the stored settings), and a toast says so, **dx : réglage non appliqué, réglages illisibles (…)**.
- **Implications**:
  - The side panel sits beside the transcript in fullscreen mode from 110 columns, above the prompt otherwise. It is one pane whose content changes (notes, settings or a terminal) without closing, so nothing flickers; a row of tabs atop it leads from one to another and to each background task's terminal.
  - A click in the panel (its tabs, the notes' tabs and links, the settings' controls) never selects text, however the pointer moves; they are pressed with the pointer's left button only, not the keyboard, and act at its release, but the number steppers act as soon as it is pressed. The custom hex color is typed in a plain input field. The band's icons stay plain buttons ([ADR 0005](../adr/0005-panel-presses.md)).
  - A change made in one session shows in another when the band's `⚙` icon is next clicked there (the panel's **Réglages** tab does not read the settings again); a change made there first reads them again from the store, so it keeps the other session's (unless a change of that session is still unsaved, see **Data**).
  - Each copy of the plugin (installed, loaded with `--plugin-dir`) keeps its own settings.

## Notes

The `✎` icon shows the notes in the side panel, for you alone (a second click closes it), with three tabs: **Global** (every session), **Projet** (the session's project) and **Session**.

- **Effect**: a sheet per tab, written as in a plain notepad: click it to type, Enter starts a new line, Tab inserts two spaces, the arrows, Home, End and Page Up/Down move the cursor, Ctrl+← / Ctrl+→ a word at a time, Ctrl+Backspace erases the word before and Ctrl+Delete the one after, Escape gives the keyboard back to the prompt. What is written stays shown and is saved on every change. Under the session tab, the other sessions' notes, latest first, as many rows at a time as set; when there are more, the list's title row shows where it stands (`9–16 / 23`) and two arrows, `▲` and `▼`, that move it a page, and the mouse wheel over the list moves it as many rows as the wheel scrolls (a row per notch, more when notches come fast; elsewhere in the pane, or with every note shown or the list at its end that way, the wheel does what it always does). Click one to open it, then **Supprimer cette note** to delete it, or **← Session actuelle** to come back.
- **Data**: kept in dx's store ([ADR 0004](../adr/0004-settings-and-notes.md)) on every change; the project note under the session's project root, the session note under the session's id. An emptied note is deleted; nothing is deleted otherwise. **Supprimer cette note** also deletes the links to that session (`/clear`, below).
- **Loading**: the notes are loaded when the session starts. If that fails, they are loaded again each time the pane is shown; while they cannot be, the pane says **Notes indisponibles** with the reason and a **↻ Réessayer** button, and the debug log (`claude --debug-file <file>`) has a `dx : notes non chargées` line.
- **`/clear`**: a `/clear` empties the conversation, not the session: the **Session** tab keeps its note, and the pane stays on the tab shown. Claude Code goes on under a new session id; dx links it to the old one (a small `notes.link.<id>` entry in its store) at the next load, only in the Claude Code process that ran the `/clear`, which dx remembers in memory, never in another conversation open meanwhile. Should dx be reloaded, or another conversation resumed (`/resume`), between the `/clear` and that load, the link is not made: the old note stays listed among the other sessions. Deleting another session's note with **Supprimer cette note** also deletes the links pointing to that session; emptying a note in its sheet, the current session's or another's, keeps them.
- **Implications**:
  - The notes are not sent to Claude: what a pane shows never reaches its context. They are not hidden from it either: the store is a plain-text file under `~/.claude`, which Claude could read if it went looking for it.
  - A note opened in two sessions at once: what one writes shows in the other within about a second, no tab changed (dx reads the shown note again every second while the notes pane is open). If both write within the same second, the last one written wins.
  - They stay on the machine, follow you elsewhere only if `~/.claude` is synced, and belong to the copy of the plugin that wrote them.
  - A note holds at most 95,000 characters (Claude Code lets the editor receive and send 100,000, less a margin), counted as the note is encoded for the editor (as JSON): a line break, carriage return, tab, backspace, form feed, double quote or backslash counts as two; any other control character, all rare and invisible, or half an emoji split from its pair, as six; most emoji as two; any other character, accented letters included, as one. Past the limit, an edit that lengthens the note is not applied: a key typed is ignored, a paste refused whole, never cut. Shortening the note always works in the editor, even one an older version of dx kept past the limit.
  - A note the editor cannot receive at all (its props, the note encoded as above plus a few hundred characters, past 100,000 characters of JSON: a note written before the limit existed, or by another copy of dx) is not opened in it: the sheet shows **Note trop longue pour être modifiée ici (… caractères) : elle reste enregistrée telle quelle.**, its length counted as above, and the note stays in the store unchanged. Another session's note can still be deleted with **Supprimer cette note**. In the list of other sessions, rows are cut to the pane's width.
  - dx's whole store holds at most 3.8 MiB of JSON text (Claude Code refuses to write past 4 MiB; the margin is for the settings and dx's other keys). dx keeps an estimate of its size, measured after each load of the notes (at the first drawing of the notes pane or the first save that follows), then updated by its own note saves and link deletions; its other writes (settings, last tab shown, `/clear` links) and other sessions' are seen at the next measurement. This limit, too, holds as you type: the editor is told the longest the note shown may grow to, its length plus as many characters as the room left surely holds at 6 bytes each (the most one character takes once written as JSON, a control character being written `\u00XX`), once what the note's entry takes besides its text is set aside. Past it, an edit that lengthens the note is not applied, as above, with **store presque plein : supprimez d'anciennes notes**. Deleting other sessions' old notes makes room, and typing works again at once. While the room left is too short for a full-length note, the estimate is measured again every second as long as the notes pane is open, so room another session frees is taken up within about a second, the note left open.
  - The save checks the limit again, against the same estimate, measured again before refusing (at most once a second). It catches what typing cannot: an edit that weighs more than its new characters (a letter replaced by a control character), or room another session took since. Such a save is refused, even one that shortens the note, as long as the store stays past its limit; emptying a note is never refused for size. The text of a refused save stays in the editor only: it is lost when the editor is drawn anew (another tab or note shown, the panel closed). Another session filling the store while dx's estimate is still far from the limit is not seen: Claude Code then refuses the write past 4 MiB, which is shown as below.
  - A save never fails silently: a refused edit, a refused save or one Claude Code rejects shows **⚠ non enregistré** in red where the save time (`✓ dd/mm hh:mm`, or `vide` when the note is empty) stands, the reason on the row below (**note trop longue (95 000 caractères au plus)**, **store presque plein : supprimez d'anciennes notes**, **notes non chargées : …** when the notes could not be loaded to save it, or Claude Code's own message after `store : `). The warning belongs to the note concerned: it shows only when that note is shown, and goes when that note saves; a save of another note leaves it. One exception: when the notes could not be loaded and the note is the project's, whose key dx cannot know then, the warning shows with every note until the next save succeeds. An edit refused as you type was never applied, so nothing is lost; the text of a refused save is lost as said above.

## Turn off

`/plugin` > Installed > `dx` > Disable, or `claude plugin disable dx@cc-plugins`; uninstall with `claude plugin uninstall dx@cc-plugins`.

Most of what the band shows can be turned off on its own in the settings (above). The notes, and the `✎` and `⚙` icons that open the notes and settings panes, cannot: they go only with the whole plugin. Neither can the band itself, only folded (`ctrl+x ctrl+a`, or `[-]`) or turned off with the plugin.
