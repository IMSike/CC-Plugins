# dx — developer experience

**English** · [Français](../../fr/plugins/dx.md)

Install: `/plugin install dx@cc-plugins` (after `/plugin marketplace add IMSike/CC-Plugins`). Requires Claude Code 2.1.310 or later.

If one of dx's parts (settings, notes, activity, band, copies for Remote Desktop, clickable paths) fails to start, at the session's start or a turn's, the others start all the same, and the debug log (`claude --debug-file <file>`) has a `dx : démarrage échoué, … (…)` line naming it (`réglages`, `notes`, `activité`, `bandeau`, `presse-papiers TSE`, `chemins`; followed by `, tour` at a turn's start), with the reason in parentheses.

## Status band

```text
╭─ ✻ Opus 5.5 ─ ▰▰▰▰▱ xhigh ────────── ~/repo/app ⎇ dev ─ ✎  ⚙  ─╮
│ ctx  22% ◎◎◎◎◎◎◎◎◎◎···································         │
│ 5h   12% ◎◎◎◎◎◉◉◉◉◉◉◉◉◉·······························  ↻ 3h24 │
│ 7j   71% ◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◎◉◉◉◉◉◉◉◉◉◉◉◉············· ↻ 1j15h │
╰─ ✻  ✻  ▣  ▣  ─ durée 1m04 · fin 14:32 · total 1h12 · 24k/200k ─╯
```

On screen, colors tell apart what plain text cannot: on `5h`, the `◉` are the pale budget; on `7j`, they are consumed ahead of the pace, in full color. In the bottom border, `▣` stands for the terminal icon, a Nerd Font glyph; in the top border, `✎` and `⚙` stand for the notes and settings icons, two more (nf-fa-edit and nf-oct-gear by default).

- **Effect**: an instrument panel directly above the prompt, framed and laid out in the terminal's width.
  - **Top border**: the spark `✻`, lit in Claude's color while Claude works and grey at rest; the model (`claude-opus-5-5` reads `Opus 5.5`; a model id ending in `[1m]`, for the 1M context window, adds `(1M)`); the reasoning effort as a five-step meter (`low` ▰▱▱▱▱ to `max` ▰▰▰▰▰) and its name, or its number for a budget in tokens: Claude Code tells a plugin the effort really used (`--effort`, `/effort`, an environment variable, a level lowered for the model) only with a request, so until a request of the main conversation made since dx started confirms it, and again after the `effortLevel` setting or the model changes, the band shows the setting, meter and name grey and followed by `?` (`xhigh?`), then the effort the request was sent with, and nothing for a model that takes no effort (a subagent's request confirms nothing, nor one Claude Code sends to a fallback model, whose effort is that model's; the confirmation is kept in dx's memory: a `/clear` keeps it, a reload of dx forgets it); the current directory, the home folder shown as `~`, cut from the left when space runs out; the Git branch after `⎇` (a short commit when detached); at the right end, `✎` and `⚙` open the notes and settings panes (below).
  - **Gauges**: `ctx`, share of the context window used by the last request, measured by default against the auto-compaction threshold, the token count at which Claude Code compacts the conversation (its window, the model's or a smaller one set with `CLAUDE_CODE_AUTO_COMPACT_WINDOW` or the settings, less the reserve it keeps), else against the model's window (see **Status bar**, below); `5h` and `7j` (`7d` if so set, below), share of the 5-hour and 7-day usage limits used. Each gauge is a string of beads: double circles `◎` for what is consumed, on a track of small dots `·`, drawn in a **heat gradient**: every cell takes the color of its position, green, yellow, orange, then red, each color blending into the next and halfway between them at 25%, 50% and 75%, so a gauge reddens as it lengthens. The percentage takes the color its value reaches.
  - **Pace** on `5h` and `7j`: the pace is where a steady consumption would stand at this point of the window (the share of the window already gone). The gap between it and the consumption is drawn in dotted circles `◉`. Behind the consumption, pale `◉` follow it: the budget, what can still be used without running ahead. Ahead of it, the consumed beads past the pace turn into `◉` in full color: usage is faster than the window allows on average, by that many beads.
  - **Shuttle**: a glow, fading out over the beads behind it, glides along the consumed beads from the first to the last, easing in and out, in 0.4 s plus 22 ms per bead (2.6 s at most: a short gauge is a quick course), then rests 3.5 s. The gauges' shuttles leave 1.4 s apart, then each keeps its own rhythm (its course depends on its length), so they may overlap; a gauge with fewer than 6 consumed beads has none. It moves by fractions of a bead, its light shared between two neighbours. It is drawn by the terminal itself (a `Client` element and its frame clock): the band is not recomputed for it, and nothing moves while it rests.
  - **Countdown**: `↻ 3h24`, time left before the window resets. When the window will run out before then at the rate it has been used since it started, the countdown gives way to `⚠ 1h10` in red: the time left before it runs out (no forecast during the first 2% of the window).
  - **Frame**: yellow. Two glints go round it, half a lap apart, a lap every 18 s, each a brighter stretch of the line, fading in over 4 cells ahead of it and out over 10 cells behind it; like the shuttle, they are drawn by the terminal itself.
  - **Bottom border**: on the left, what runs beside the conversation (below); on the right, the last turn's duration (`durée`, counting while Claude works) and the time it ended (`fin`), the session's total duration (`total`), and context tokens over the window the `ctx` gauge measures against.
- **Data**: read from Claude Code itself (`$.session.usage()`, `$.session.model()`, the `effortLevel` setting, the effort each request is really sent with), the main loop's turns (`turn.start`, `turn.complete`), and the repository's `HEAD` (read only): a `.git` looked for in the session's folder, then in each parent up to the root (a `.git` folder without a `HEAD` is passed over, as Git does), and its `.git/HEAD` read, or for a worktree or a submodule the `HEAD` its `.git` file points to; nothing is sent anywhere. Refreshed at the end of each turn and every 30 seconds, a refresh that fails keeping the last figures (when refreshes start failing, the debug log, `claude --debug-file <file>`, has a `dx : bandeau non rafraîchi` line); the turn's duration every second while it runs.
- **Implications**:
  - The `5h` and `7j` lines only appear with a Claude subscription (the API reports no limits otherwise); `ctx` shows `—` until the first response, and after a compaction until the next one.
  - `total` counts from the session's start, for a resumed session from its first launch; a `/clear` starts it over.
  - The band takes up to five rows: one per gauge shown, and its two borders. It is drawn in the terminal and the desktop app; other surfaces (VS Code, mobile) do not show it.
  - The repository is located once per directory, its `HEAD` read again on each refresh: a branch switch shows, and a `HEAD` or a worktree's `.git` file Git is rewriting at that moment, or a lookup refused for a moment (a guard), only hides the branch until the next refresh. A repository on a network path (`\\server\share`) never shows its branch: Claude Code's file access does not reach network paths. A `.git` file that names no repository, or a removed worktree's, shows no branch, and a repository created after the session started (`git init`) does not show its branch either, until the next session or a reload.
  - It is not the status line: it sits **above** the prompt, and a `statusLine` configured in `settings.json` keeps being shown under it. Remove `statusLine` to avoid seeing the same figures twice.
  - The frame, the gauges, the effort meter and the branch use characters (`╭ ◎ ◉ ▰ ⎇`) present in common terminal fonts (Cascadia, Nerd Fonts); the robot and terminal icons, and the default notes, settings and monitor icons, need a [Nerd Font](https://www.nerdfonts.com).
  - While Claude Code shows a survey in that band, the survey takes its place.
- **Fold / unfold**: `ctrl+x ctrl+a`, or click `[-]`.

## Subagents and background tasks

The left of the bottom border holds an icon for each subagent and background task of the session, up to five of a kind (as set, below), then a count (`+3`). Working and waiting subagents are two kinds, each capped on its own: up to ten subagent icons by default. Agent CLIs for Claude Code, agent CLIs for Cursor, shells and monitors are a kind each.

- **Effect**:
  - **Subagent**: `✻` in Claude's color, turning like Claude Code's own spinner (`· ✢ * ✶ ✻ ✽`, there and back, 200 ms a step) while it works, still and dim while it waits.
  - **Agent CLI** run in a background shell: a robot, in Claude's color for Claude Code, grey for Cursor.
  - **Background shell** (`run_in_background`): a terminal icon, grey; a `Monitor`: a pulse (nf-oct-pulse), grey, or the glyph chosen in the settings.
  - **Click a subagent**: its transcript takes the main view, as from the tasks list; its icon is underlined meanwhile. Click it again to come back to the main conversation. Should Claude Code refuse the switch, a toast says `dx : ` followed by its reason.
  - **Click a shell, an agent CLI or a monitor**: the side panel shows its command, whole, wrapped over as many lines as it needs, then the end of its output (as much of its last 200 lines as fits), read again every second: **Fichier de sortie pas encore trouvé, dx le cherche encore.** while its file is not found (not written yet, or its folder not found yet), **Dossier temporaire de Claude Code introuvable ou illisible, dx le cherche encore.** when the `claude` folder of the temporary directory is missing or cannot be listed, **Pas encore de sortie.** while the file is there but empty, **(sortie illisible : <reason>)** when it cannot be read, with the reason; only its last 64 KiB are read. Its tab atop the panel reads the command's first line, cut at 24 characters. Click the icon again to close the side panel.
  - An icon leaves the border when its subagent finishes, or its task is stopped or ends.
- **Data**: the session's agents (`$.agent.list()`); the background tasks, from the tool calls that start and stop them and from Claude Code's task notifications (read as they enter the session, so that an end is known in the focus view too, which draws no notification row), and from the last line Claude Code writes in a task's output as it ends (`[exited with code N]`, `[killed]`), so that an end no notification reported (one handed to Claude during a turn) is known too; their output, read from the file Claude Code writes it to, `<task>.output` in the session's `<session>/tasks` folder under one of the folders of `claude` in the temporary directory as Claude Code takes it (`CLAUDE_CODE_TMPDIR`, else the system's temporary directory as Node.js finds it: `TEMP`, `TMP`, then `temp` in the Windows folder on Windows; `TMPDIR`, `TMP`, `TEMP`, then `/tmp` elsewhere): dx makes no assumption on that folder's name (the project's directory, encoded, for older sessions; an identifier of Claude Code's own since) and lists `claude` to look into each for the task's own file (the newest, should several hold one), the file alone telling the folder: a session resumed across the change of names has both folders, the older never written again. It looks when a task starts and, while the file is not found, at each refresh of the task shown for 30 s after it is shown, then every 10 s; the task's own session is looked into, even after a `/clear`. Once a task's file is found, its folder is kept for the session, and moved to the new session's after a `/clear`. An agent's result naming its output file gives the folder outright. A task whose file is not in the folder kept is looked for the same way, and the folder found holding it replaces the one kept. A variable of the temporary directory that is empty or cannot be read is passed over for the next. To tell an agent CLI in a shell and to catch an end Claude Code did not report, dx reads the system's process list ([ADR 0003](../adr/0003-system-process-list.md)): Windows PowerShell on Windows (by its full path, run from `%SystemRoot%`), `ps` through `sh -c` elsewhere, only while a task is due for a check (2 s after it starts, then after 10 s, 1 min, 5 min, then every 15 min). It keeps only the shells' ids and whether an agent CLI runs under them; nothing is sent anywhere.
- **Implications**:
  - On Windows, a check costs about 0.3 s of CPU on one core and 80 MB of memory for its duration, in the background; with no background task, nothing is read. Should the read fail, the icons follow Claude Code's signals alone.
  - Every 3 s (or as the refresh is set, below), each followed task's output file is checked for its size, and its last kilobyte read once that size held still from one refresh to the next, to find the line written as the task ends; it is read again only once its size has changed and held still again. A task is not read while it keeps writing, so its end is seen at the second refresh after its last line.
  - A shell is recognised by the words of its command: two background shells running the same command can each be matched to the other's process, the agent CLI or the end it reveals then being the other one's; the output shown stays right.
  - While a task's output file is not found, each look lists `claude` in the temporary directory and checks one path per folder in it: every second for 30 s, then every 10 s, for as long as the task is shown.
  - While the spinner is on and a working subagent's icon is shown, the band is redrawn on each spinner step; while a turn runs, every second.
  - Unchecking **Sous-agents et tâches** in the settings only hides the icons: dx still follows the tasks and reads the process list as above, and each task's terminal stays among the panel's tabs.
  - Reloading the plugin forgets the tasks under way: only the tasks started afterwards get an icon.

## Settings

The `⚙` icon shows the settings in the side panel; a second click closes it. A change applies at once and is kept across sessions. The pane has two tabs drawn at its top, **Apparence** (how the band looks) and **Fonctions** (what dx does); it opens on the last one shown, kept in dx's store and read again when dx starts, as the notes' last tab is (a tab chosen in another session shows here from the next start of dx).

- **Effect**:
  - **Apparence** tab:
    - **Display**: each element of the band on or off: model, effort, directory, Git branch, each gauge, countdowns, subagents and tasks; the 7-day gauge's label (**Libellé de la jauge 7 j**), `7j` (French, by default) or `7d`, which also sets the day unit of the durations the band shows, its countdowns, the red `⚠` forecast and the session's total: `1j15h` with `7j`, `1d15h` with `7d`.
    - **Bottom border**: the turn's duration, its end time, the session's total and context tokens, each on or off and moved up or down with `↑` `↓`; how many subagent icons, and how many task icons (agent CLIs, shells, monitors), of a kind before a `+N` count (5 each by default, 1 to 10).
    - **Animations**: the frame's glints, the gauges' shuttle, the subagents' spinner, each on (by default) or off; the speed of the glints and the shuttle (slow, half as fast; normal, by default; fast, twice as fast). The spinner keeps Claude Code's pace whatever the speed. Animate only while Claude works (off by default): the glints and the shuttles rest otherwise; with **… ou qu'un sous-agent ou un shell est actif** (checked along with it by default), they also run while a subagent works or a background task runs. The subagents' spinner turns only while its subagent works in any case.
    - **Colors**, each picked from a list of named colors or typed as hex (`#58a6ff`): the frame (the theme's warning color, yellow, by default), the effort meter and the branch (Claude's color by default), the gauges (the heat gradient by default, or one color), the bottom border's text (dim by default). The band shows a change at once. A typed text that is no six-digit hex color is not applied, and the pane says so in red under its field, **⚠ couleur non appliquée : …**, until its text changes, a color is applied for that element (typed, picked from its list, or by **Réinitialiser**), the pane is shown again (the `⚙` icon, the **Réglages** tab) or turned to its **Fonctions** tab, or dx is reloaded.
    - **Gauge thresholds**: where the heat gradient turns orange (50% by default, from 10% to 90%) and red (75% by default, from 5 points above orange to 95%), by steps of 5; yellow sits halfway to orange.
    - **Icons**: the glyphs of the notes and settings icons (nf-fa-edit and nf-oct-gear by default), and of a monitor's (nf-oct-pulse by default; also an eye, a radar, a broadcast, a bell), among a few Unicode and Nerd Font ones; one the terminal's font lacks draws as a blank or a box.
  - **Fonctions** tab:
    - **Notes**: the tab the pane opens on (**Global** by default); whether it takes up the last tab shown instead (on by default); how many other sessions' notes are listed at a time (8 by default, 0 to 20); at 0 the list disappears, and other sessions' notes can no longer be opened or deleted from the pane. Whether a note's selection is copied to the clipboard as soon as it is made, as the terminal copies its own (on by default): as the mouse button comes up, and at Ctrl+A.
    - **Clipboard** (**Presse-papiers**, Windows only): **Réparer les copies pour le Bureau à distance (TSE)** (off by default) writes the clipboard again after each copy dx sees, so that a paste into a Remote Desktop session works (see Copies for Remote Desktop, below).
    - **Paths** (**Chemins**, inside herdr on Windows alone): **Chemins cliquables** (on by default) makes the paths of Claude's replies links that herdr's `imsike.links` plugin opens on a ctrl+click; the line under it says what is missing, or whether they are on (see Clickable paths, below).
    - **Status bar** (**Barre d'état**): refresh (**Normal** by default): how often the activity (subagents, ends of background tasks: every 3 s) and the band (model, effort, branch, countdowns, gauges: every 30 s) are read again; **Lent** twice as seldom, **Rapide** twice as often, applied at once. The process list, the terminal shown and the animations keep their own pace. Hide the `5h` gauge while its window has not started (on by default); off, its row is drawn empty. Measure the context gauge against the auto-compaction threshold (on by default): with a threshold of 300k and 150k tokens in context, `ctx` shows 50% and the bottom border `150k/300k`, and compaction runs around 100% (Claude Code compares that threshold to its own estimate of the context); off, against the model's window. That threshold is read from Claude Code's estimate of the context (the one `/context` shows, computed locally, no request sent), at most every 5 minutes and at each change of model; with auto-compaction off, or the threshold unknown or 0, the model's window is used. As observed in Claude Code 2.1.330 (none of what follows is documented, and it may change): that threshold ignores `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`; with that percentage, compaction runs earlier than the gauge shows (set to 30 on a 1M window, around 294k instead of 967k). The window itself is followed, whether it comes from `CLAUDE_CODE_AUTO_COMPACT_WINDOW` or `--autocompact`; the variable wins over the flag, which then has no effect.
  - **Réinitialiser**, at the bottom of either tab, puts every setting back to its default, those of the other tab too.
  - **`[ 📁 dossier .claude ]`**, left of **Réinitialiser** (on Windows alone), opens Claude Code's own configuration folder in the File Explorer ([ADR 0007](../adr/0007-configuration-folder.md)): `CLAUDE_CONFIG_DIR` when set (written with backslashes or slashes, `/c/…`, `~` or relative to the working directory; the button then shows its name, `[ 📁 dossier claude-config ]`), else `.claude` in the home folder. Windows PowerShell (`%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`, run from `%SystemRoot%`, so that no program of the same name in the session's folder runs in its place) opens it as a double click does (`Invoke-Item`), in a window shown: Claude Code starts a plugin's programs with their window hidden, and `explorer.exe <folder>` run directly then opens the folder in a hidden window, nothing seen (as observed in Claude Code 2.1.330). The folder alone is named, handed over in a variable of the environment, never `settings.json`: Claude Code refuses a plugin's run of a program whose argument names one of its settings files (its own rule, not documented, as observed in Claude Code 2.1.330), and dx does not work around that. From there, `settings.json` opens with a double click. dx only opens the folder, never writes in it. A click while an opening is under way does nothing. A folder that is not there, or one Windows cannot open (PowerShell's first error line), is said in red above the buttons, **⚠ dossier introuvable : …** or **⚠ dossier non ouvert : …**, until it opens, the pane is shown again, a `/clear` empties dx's state or dx is reloaded; an opening that fails after the pane was shown again says nothing.
- **Data**: kept in dx's own store, a JSON file under Claude Code's configuration directory (`~/.claude` by default; observed in its `plugins/store/` folder) ([ADR 0004](../adr/0004-settings-and-notes.md)). A change Claude Code fails to save still applies to the current session, and the pane says so in red under its tabs, **⚠ réglages non enregistrés : …** followed by Claude Code's message, until a later change saves. Until then, the next changes build on the current session's settings rather than on the store, so the save that succeeds writes them all (and replaces any change another session saved meanwhile), and the `⚙` icon, rather than reading the settings again from the store, tries to save them again: once Claude Code saves them, the warning goes. A reload of dx keeps them too, rather than reading the store over them: from dx's memory, a `/clear` before the reload included (see below), or, when dx's code is loaded anew and its memory lost, from dx's state, which a `/clear` may have emptied; settings in the state that this dx no longer reads (an update of dx changed their form), or a state Claude Code fails to read, are not taken up: the unsaved change is lost and the store read, never the defaults saved over it. A `/clear` keeps the session's settings, saved or not, and their warnings: should Claude Code empty dx's state, dx remembers them in memory, within the Claude Code process that ran the `/clear`; the settings pane, the panel's tabs and the notes follow them at once, the band from the next prompt, change or click on `⚙`, and a change starts from them, never from the defaults. A read of the store that fails leaves the settings shown as they are, a reload's included once dx has read them. Should it fail with the store never read yet, as the session starts or at a reload after dx's code was loaded anew (its memory lost), the band shows the default settings, the pane says so in red under its tabs, **⚠ réglages illisibles : … (réglages par défaut affichés)** with Claude Code's message, the debug log has the `dx : démarrage échoué, réglages (…)` line, and the store is read again as each of your prompts starts. At such a reload, when dx's state still holds settings the session showed as its own (read from the store or changed before the reload, or shown so by an earlier such reload), not the defaults shown with **(réglages par défaut affichés)**, the band shows those instead of the defaults, and the pane says **⚠ réglages illisibles : … (changement refusé tant qu'ils ne sont pas relus)**. Either way, until a read succeeds, a change is not applied (it would build on settings that are not the store's, written over the stored ones), and the pane says **⚠ réglages illisibles : … (changement non appliqué)** instead. The warning goes as soon as a read of the store succeeds: as a prompt starts, at a click on `⚙` or at a change.
- **Implications**:
  - The side panel sits beside the transcript in fullscreen mode from 110 columns, above the prompt otherwise. It is one pane whose content changes (notes, settings or a terminal) without closing, so nothing flickers; a row of tabs atop it leads from one to another and to each background task's terminal.
  - A click in the panel (its tabs, the notes' tabs and links, the settings' controls) never selects text, however the pointer moves; they are pressed with the pointer's left button only, not the keyboard, and act at its release, but the number steppers act as soon as it is pressed. The custom hex color is typed in a plain input field. The band's icons stay plain buttons ([ADR 0005](../adr/0005-panel-presses.md)).
  - A change made in one session shows in another when the band's `⚙` icon is next clicked there (the panel's **Réglages** tab does not read the settings again); a change made there first reads them again from the store, so it keeps the other session's (unless a change of that session is still unsaved, see **Data**).
  - Each copy of the plugin (installed, loaded with `--plugin-dir`) keeps its own settings.

## Notes

The `✎` icon shows the notes in the side panel, for you alone (a second click closes it), with three tabs: **Global** (every session), **Projet** (the session's project) and **Session**.

- **Effect**: a sheet per tab, written as in a plain notepad: click it to type, Enter starts a new line, Tab inserts two spaces, the arrows, Home, End and Page Up/Down move the cursor, Ctrl+← / Ctrl+→ a word at a time, Ctrl+Backspace erases the word before and Ctrl+Delete the one after, Escape gives the keyboard back to the prompt. A line wider than the sheet wraps at a word: a word that does not fit goes whole to the next row, and only a word wider than the whole sheet is cut (as is text written without spaces, such as Chinese or Japanese). The spaces where a line wraps stay at the end of the row above, past its edge if need be, where they are not drawn, as in a notepad: a row never starts with them, only a line with its indentation; the cursor among them is drawn on the row's last cell. A wide character (CJK, most emoji) counts its two cells, and an emoji or an accented letter is moved over and erased as one character, by words too. The arrows, Home and End move over the rows as drawn: up and down keep the column, End on a wrapped row stops after its text, before the spaces it ends with, or, on a row cut within a word, before its last character. Drag the mouse over the text to select part of it, or press Ctrl+A for all of it: it is copied to the clipboard at once, unless set otherwise (settings, **Notes**), and while something is selected, **Couper** and **Copier** stand beside **Coller**, to cut or copy it; typing or **Coller** replaces it, Backspace or Delete erases it, an arrow drops it. Ctrl+C and Ctrl+X do not reach the note: Claude Code keeps Ctrl+C to interrupt, and Ctrl+X starts its shortcuts (Ctrl+X X closes the panel). The note holds the mouse, so the terminal's own selection does not work over it. A paste in the terminal goes to the prompt box, as without dx; the **Coller** button pastes the clipboard into the note (see Pasting, below). What is written stays shown and is saved on every change. Under the session tab, the other sessions' notes, latest first, as many rows at a time as set; when there are more, the list's title row shows where it stands (`9–16 / 23`) and two arrows, `▲` and `▼`, that move it a page, and the mouse wheel over the list moves it as many rows as the wheel scrolls (a row per notch, more when notches come fast; elsewhere in the pane, or with every note shown or the list at its end that way, the wheel does what it always does). Click one to open it, then **Supprimer cette note** to delete it, or **← Session actuelle** to come back.
- **Data**: kept in dx's store ([ADR 0004](../adr/0004-settings-and-notes.md)) on every change; the project note under the session's project root, the session note under the session's id. An emptied note is deleted; nothing is deleted otherwise. **Supprimer cette note** also deletes the links to that session (`/clear`, below).
- **Loading**: the notes are loaded when the session starts. If that fails, they are loaded again each time the pane is shown; while they cannot be, the pane says **Notes indisponibles** with the reason and a **↻ Réessayer** button, and the debug log (`claude --debug-file <file>`) has a `dx : notes non chargées` line.
- **`/clear`**: a `/clear` empties the conversation, not the session: the **Session** tab keeps its note, and the pane stays on the tab shown. Claude Code goes on under a new session id; dx links it to the old one (a small `notes.link.<id>` entry in its store) at the next load, only in the Claude Code process that ran the `/clear`, which dx remembers in memory, never in another conversation open meanwhile. Should dx be reloaded, or another conversation resumed (`/resume`), between the `/clear` and that load, the link is not made: the old note stays listed among the other sessions. Deleting another session's note with **Supprimer cette note** also deletes the links pointing to that session; emptying a note in its sheet, the current session's or another's, keeps them.
- **Pasting**: Claude Code sends a paste made in the terminal (Ctrl+V, a right click) to the prompt box, even while a note holds the keyboard, and a plugin cannot tell where the keyboard is. To paste into a note, the **Coller** button, at the bottom right under the sheet, reads the system clipboard and inserts its text into the note shown at its cursor, which the press leaves where it was; the cursor then follows the pasted text. Line ends become plain line breaks, a tab two spaces, as the Tab key types, and other control characters are dropped; an empty clipboard, or one holding no text, pastes nothing. A paste follows the same limits as typing (below): refused whole, never cut, with the same warning; one that would make the note too long whatever the editor holds is refused before reaching it. The button is drawn only with the note's editor: not while the notes are unavailable, nor for a note too long to be edited here.
  - The clipboard is read with what the system ships ([ADR 0006](../adr/0006-system-clipboard.md)): Windows PowerShell on Windows (by its full path, run from `%SystemRoot%`), which takes about 0.3 to 0.5 s per press; `pbpaste` on macOS; on Linux, the first of `wl-paste` (Wayland, asked for text alone), `xclip` and `xsel` (X11) that reads the clipboard, one that is missing or fails giving way to the next. Nothing runs until the button is pressed. Each tool may take 5 s; past that, it is given up.
  - With none of these tools, the pane says **presse-papiers illisible : installez wl-clipboard, xclip ou xsel**; a tool that fails, **presse-papiers illisible :** followed by its own message, or by **délai dépassé (5 s)** when it took too long. Of several that fail, the first that started is the one named.
  - In a session over SSH, the clipboard the session could read is the remote machine's, not yours: dx does not read it and says **session SSH : le presse-papiers lu serait celui de la machine distante**.
  - These messages show where a refused edit's do, headed **⚠ collage impossible** in red with the reason on the row below, until the note next saves; the note is left as it was. An empty clipboard, or one holding no text, pastes nothing and says nothing, the errors `wl-paste` and `xclip` give then included.
  - A paste read while another tab is shown, or the pane closed, waits for its note: it goes in when that note is shown again, once. Only one paste waits at a time: another one read meanwhile, into another note, replaces it. Should another session have lengthened the note meanwhile past what it can take with the paste, the paste is refused whole, with the too-long warning.
- **Implications**:
  - The notes are not sent to Claude: what a pane shows never reaches its context. They are not hidden from it either: the store is a plain-text file under `~/.claude`, which Claude could read if it went looking for it.
  - A note opened in two sessions at once: what one writes shows in the other within about a second, no tab changed (dx reads the shown note again every second while the notes pane is open). If both write within the same second, the last one written wins.
  - They stay on the machine, follow you elsewhere only if `~/.claude` is synced, and belong to the copy of the plugin that wrote them.
  - A note holds at most 95,000 characters (Claude Code lets the editor receive and send 100,000, less a margin), counted as the note is encoded for the editor (as JSON): a line break, carriage return, tab, backspace, form feed, double quote or backslash counts as two; any other control character, all rare and invisible, or half an emoji split from its pair, as six; most emoji as two; any other character, accented letters included, as one. Past the limit, an edit that lengthens the note is not applied: a key typed is ignored, a paste refused whole, never cut. Shortening the note always works in the editor, even one an older version of dx kept past the limit.
  - A note the editor cannot receive at all (its props, the note encoded as above plus a few hundred characters, past 100,000 characters of JSON: a note written before the limit existed, or by another copy of dx) is not opened in it: the sheet shows **Note trop longue pour être modifiée ici (… caractères) : elle reste enregistrée telle quelle.**, its length counted as above, and the note stays in the store unchanged. Another session's note can still be deleted with **Supprimer cette note**. In the list of other sessions, rows are cut to the pane's width.
  - dx's whole store holds at most 3.8 MiB of JSON text (Claude Code refuses to write past 4 MiB; the margin is for the settings and dx's other keys). dx keeps an estimate of its size, measured after each load of the notes (at the first drawing of the notes pane or the first save that follows), then updated by its own note saves and link deletions; its other writes (settings, last tab shown, `/clear` links) and other sessions' are seen at the next measurement. This limit, too, holds as you type: the editor is told the longest the note shown may grow to, its length plus as many characters as the room left surely holds at 6 bytes each (the most one character takes once written as JSON, a control character being written `\u00XX`), once what the note's entry takes besides its text is set aside. Past it, an edit that lengthens the note is not applied, as above, with **store presque plein : supprimez d'anciennes notes**. Deleting other sessions' old notes makes room, and typing works again at once. While the room left is too short for a full-length note, the estimate is measured again every second as long as the notes pane is open, so room another session frees is taken up within about a second, the note left open.
  - The save checks the limit again, against the same estimate, measured again before refusing (at most once a second). It catches what typing cannot: an edit that weighs more than its new characters (a letter replaced by a control character), or room another session took since. Such a save is refused, even one that shortens the note, as long as the store stays past its limit; emptying a note is never refused for size. The text of a refused save stays in the editor only: it is lost when the editor is drawn anew (another tab or note shown, the panel closed). Another session filling the store while dx's estimate is still far from the limit is not seen: Claude Code then refuses the write past 4 MiB, which is shown as below.
  - A save never fails silently: a refused edit, a refused save or one Claude Code rejects shows **⚠ non enregistré** in red where the save time (`✓ dd/mm hh:mm`, or `vide` when the note is empty) stands, the reason on the row below (**note trop longue (95 000 caractères au plus)**, **store presque plein : supprimez d'anciennes notes**, **notes non chargées : …** when the notes could not be loaded to save it, or Claude Code's own message after `store : `). The warning belongs to the note concerned: it shows only when that note is shown, and goes when that note saves; a save of another note leaves it. One exception: when the notes could not be loaded and the note is the project's, whose key dx cannot know then, the warning shows with every note until the next save succeeds. An edit refused as you type was never applied, so nothing is lost; the text of a refused save is lost as said above.

## Copies for Remote Desktop

On Windows, a text copied in Claude Code (a mouse selection, Ctrl+Shift+C, `/copy`) may paste as nothing into a Remote Desktop session (RDP, TSE, a Hyper-V VM in enhanced session), until the next copy. Claude Code writes the clipboard twice for each copy: the terminal's write (OSC 52; herdr writes it itself), then Windows PowerShell's, about 0.2 s later, and that second write, so soon after the first, breaks Remote Desktop's clipboard redirection. Writing the text again once, a moment later, mends it ([ADR 0008](../adr/0008-remote-desktop-clipboard.md)).

- **Effect**: with **Réparer les copies pour le Bureau à distance (TSE)** on (settings, **Presse-papiers**; off by default, offered on Windows alone), about 1.5 s after each copy dx sees (up to about 2 s for a selection), dx writes the clipboard's text again, once, unchanged (to the character, line ends included):
  - **automatic**: a mouse selection Claude Code copies as it is made (its **Copy on select**, on by default in fullscreen mode): dx reads your selection every half second, and rewrites the clipboard a second or so after the last change, if the clipboard then holds the selected text (tried once more 2 s later when it does not yet); `/copy` (not a copy made from the picker it shows when a reply holds several code blocks: use `/dx-tse`); a plugin's copy, dx's notes' included.
  - **on demand**: `/dx-tse` rewrites the clipboard at once, whatever the setting, and says what it did (shown to you alone, not sent to Claude). Run it after a copy dx does not see: Ctrl+Shift+C when **Copy on select** is off, a copy from `/copy`'s picker, the same text selected twice in a row, `/export` to the clipboard, or a paste that came too soon.
- **When to turn it on**: you paste what you copy in Claude Code into a Remote Desktop session, and get nothing. Outside herdr, Windows Terminal's `"compatibility.allowOSC52": false` setting (in its `settings.json`, under the profiles' defaults) does the same with no process: the terminal ignores OSC 52 and PowerShell's write stands alone; that setting is the terminal's, for every program run in it. In herdr, which writes the clipboard itself, only dx's setting helps (herdr's side: [herdr#5687](https://github.com/herdrdev/herdr/issues/5687)).
- **Implications**:
  - Each rewrite starts Windows PowerShell 5.1, `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`, run from `%SystemRoot%`: about 0.6 to 0.8 s and, as ADR 0003 measured, about 300 ms of CPU and 80 MB of memory while it runs. The text never leaves that process: it reads the clipboard and writes it back by the Win32 API in one go, the API declared in memory (no C# compiled, nothing written to the temporary folder). Under PowerShell's Constrained Language Mode (an AppLocker or WDAC policy), that declaration is refused: the rewrite fails, said in the debug log alone.
  - The clipboard is left as it is when it holds anything other than plain text (an image, files, formatted text: a rewrite would drop them; a password manager's copy, which asks to be kept out of the history), holds no text, or (after a selection or a plugin's copy) holds another text than the one copied.
  - Windows' clipboard history (Win+V) gets one more entry per rewrite, the same text again.
  - A paste made before the rewrite (about 1.5 s after the copy) may still find nothing; `/dx-tse` mends it.
  - With the setting on, your selection is read every half second (a call inside Claude Code, no process), in fullscreen mode alone; nothing is read and nothing runs while it is off. A failed rewrite says why in Claude Code's debug log alone (`dx : sélection, presse-papiers non réécrit : …`), as does a clipboard left alone, with every format it held.
  - On macOS and Linux the setting is not offered and `/dx-tse` does not exist.
- **Turn off**: the **Réparer les copies pour le Bureau à distance (TSE)** setting, off by default.

## Clickable paths

On Windows, inside [herdr](https://herdr.dev), the paths Claude writes in its replies become links, and a ctrl+click on one opens it through herdr's `imsike.links` plugin, from [Herdr-Plugins](https://github.com/IMSike/Herdr-Plugins) ([ADR 0009](../adr/0009-clickable-paths.md)). What a click does (a preview in herdr, the file selected in the File Explorer, or the program Windows associates with it) and what it refuses is set in that plugin, never in dx: see [its page](https://github.com/IMSike/Herdr-Plugins/blob/main/docs/en/plugins/links.md). dx makes the links; it opens nothing itself.

- **Effect**: in each reply's text as the terminal draws it (the stored message, and what Claude reads back, are unchanged), each path that leads to a file or a folder becomes a link, its text as written: a word of plain text (`src/app.ts:12`, `~/bin`, `C:\repo\README.md`, `/c/Users/…`, `%TEMP%\log.txt`), a path between double quotes (`"C:\mes notes\a.txt"`), or inline code holding a path (`` `C:\mes notes\a b.txt` ``). A path starts with a drive (`C:\`, or as Git Bash and WSL write it, `/c/`, `/mnt/c/`), the home folder (`~/`), one of a few Windows variables (`%TEMP%`, `%LOCALAPPDATA%`, `%USERPROFILE%`…, the link leading where the variable does), or is relative to the working directory; it holds only letters of any script, decimal digits, `. _ - + ~ @ ( ) '` and separators. A word is a path whole or not at all: the punctuation and emphasis marks around it are left out (`(src/a.ts)`, `src/a.ts.`, `**src/a.ts**`). A line or a range goes with the link: `src/a.ts:12`, `src/a.ts:12-14`. Claude Code draws it as its other links, its text alone; herdr hands a ctrl+click on any of its rows to the plugin. The link's URL holds the path and the lines alone: `dx-open:///C:/repo/src/app.ts#L12`. [ADR 0009](../adr/0009-clickable-paths.md) gives the whole grammar and its limits.
- **Not linked**: code blocks and spans, raw HTML, autolinks, the links Claude writes itself (their text and their target), images and reference definitions, left as written; a word holding any other sign (`src/a.ts#L5`, `100%.txt`, `Q&A/x.md`, `x².md`): no part of it is read as a path; another root (`/tmp/x`, `\\server\share`) or scheme (`https:`, `file:`); a path holding spaces written bare (`C:\mes notes\a.txt`: write it in quotes or code), while a word of letters alone next to a path is read as prose (`C:\Program Files` written bare links `C:\Program` when that exists); a path markdown would draw otherwise than written, or that a link would change (`__init__.py` written bare, `src\_a.ts`); a word Claude Code makes a link of (`www.example.com/a.html`, `docs/www.readme.md`, `a@b.com`), and a path glued to a web address (`` https://x.com/docs:`src/a.ts` ``), which Claude Code's link would take in; a short 8.3 name (`C:\PROGRA~1\…`: the file it leads to could be any); a path that leads nowhere, or whose check on disk takes too long; one that lands (symbolic links followed) where herdr's plugin refuses (on a network share, 260 UTF-16 units long or more, a device's name such as `con.txt`), or where dx refuses (a name holding a sign outside dx's list, or ending with a period or a space); a drive's root, the working directory and the home folder; Claude Code's own settings files (`.claude/settings.json`, `.claude/settings.local.json`, `.claude/cowork_settings.json`, those of `CLAUDE_CONFIG_DIR` and of the folder where Claude Code's configuration folder lands), as written or where the path lands: Claude Code refuses a plugin to hand them to a program, and dx does not work around that through another one; the `[ 📁 dossier .claude ]` button opens their folder. A path whose landing Claude Code does not say (a hook withheld it) is not linked either: it, or a folder above it, may be a link to anywhere. A very long reply has no path linked, as Claude Code then draws its links without hyperlinks. ADR 0009 gives every case and limit.
- **The model's links**: a link Claude writes itself, a `dx-open:` one included (`[la config](src/config.ts)`, `[README.md](dx-open:///C:/x/tool.exe)`, `<dx-open:…>`), is left as written, its text and its target, as is code of every form. dx does not tell the model's `dx-open:` links from its own: the herdr plugin is the sole guard, applying its own rules to any `dx-open:` link it is handed, whoever wrote it (the model, another pane, another program).
- **Limits**: Claude Code reads replies with its own Markdown reader, which dx approximates. In rare replies, a linked path then shows its address after it (`src/a.ts (dx-open:///C:/…)`): when the reply holds an HTML tag left open (`<code>`, `<kbd>`, `<a …>`…), Windows line endings (CRLF), or ends with a single space after a list item; or its link shows raw, after a tab following a list or quote marker (`1. <tab>src/a.ts`). Inline code right after a `~` (`` ~`src/a.ts` ``) loses its backticks once linked. A reply holding no Markdown sign, which Claude Code draws as is, is read as Markdown once dx links a path in it (`a\.b` then shows as `a.b`); the path stays clickable. [ADR 0009](../adr/0009-clickable-paths.md) lists every case.
- **Requirements**:

  | Where | What | Why | Said by dx |
  |---|---|---|---|
  | Claude Code's `settings.json`, `env` | `"FORCE_HYPERLINK": "1"` | herdr is unknown to Claude Code, which would otherwise write each link's URL after its text: dx then makes no link | yes |
  | herdr | `imsike.links` installed and enabled: `herdr plugin install IMSike/Herdr-Plugins/links` | it opens the links | yes |
  | herdr's `config.toml` | mouse capture on (`ui.mouse_capture`, the default) | a link's click reaches a plugin only then | no |
  | Windows Terminal's `settings.json` | `"experimental.detectURLs": false` under `profiles.defaults` | Windows Terminal otherwise hands a ctrl+clicked `file://` URL found in the screen's text to Windows before herdr sees it: turned back on, a `file:` URL Claude writes can again be opened by Windows with its associated program, which may run it | no |

- **Detection**: as the session starts, dx reads its environment (`OS`, `HERDR_PANE_ID`; inside herdr, `FORCE_HYPERLINK` and the variables Claude Code reads to decide on hyperlinks, `CLAUDE_CONFIG_DIR`, `HERDR_BIN_PATH` and the variables a path may start with, once); inside herdr alone, on Windows, it asks where Claude Code's configuration folder lands (`$.fs.stat`, 10 s at most), and runs `herdr plugin list --plugin imsike.links --json` (herdr by the path herdr sets in `HERDR_BIN_PATH` when that is an absolute path with a drive, else found on the `PATH`; run from `%SystemRoot%`, else `%windir%`, and not run when neither is set; given up after 10 s; asked again when it fails or is late, after pauses of 5 s, 30 s, 1 min and 2 min, each within 10 % either way), the session's start not waiting for it. The plugin listed, enabled, with its `dx-open` link handler: the links are made, and the replies already drawn are drawn again with them; anything else, herdr missing or failing five times included: none. A plugin installed or enabled during a session takes effect at the next session. The settings' **Chemins** line says, several at once separated by ` ; `, `recherche du plugin herdr imsike.links…` (also between the attempts, up to five minutes), `plugin herdr imsike.links introuvable : herdr plugin install IMSike/Herdr-Plugins/links`, `herdr ne répond pas : plugin imsike.links non vérifié (à la prochaine session)`, `dossier du système inconnu (SystemRoot, windir) : plugin imsike.links non vérifié`, `FORCE_HYPERLINK=1 manquant dans env de settings.json`, `FORCE_HYPERLINK désactive les hyperliens : le mettre à 1 dans env de settings.json` (set to `0`, `false`, `no` or `off`, or a number read as 0), `ctrl+clic sur un chemin des réponses pour l'ouvrir` or `désactivés`; the debug log has, as the session starts inside herdr, `dx : chemins cliquables, hyperliens oui`, `dx : chemins cliquables, hyperliens non (FORCE_HYPERLINK=1 les active)` or `dx : chemins cliquables, hyperliens non (FORCE_HYPERLINK les désactive)` (whether Claude Code draws links as hyperlinks), then `dx : plugin herdr imsike.links absent ou désactivé`, `dx : liste des plugins herdr en échec, essai … (code …)`, `dx : liste des plugins herdr illisible, essai … (…)` or `dx : dossier du système inconnu (SystemRoot, windir), liste des plugins herdr non lue`.
- **Implications**:
  - Each path is checked on disk once as its reply is drawn (`$.fs.stat`, no process), the answer kept a few minutes (a few seconds for a path that leads nowhere, as a reply may name a file before it is written); a drawing waits a fraction of a second at most for those checks, and a path whose check is late is linked when it answers, the reply drawn again, the drawings meanwhile not waiting for it; a check is not asked again before it answers, as Claude Code bounds no file system call and a dead network drive may never answer: the path stays unlinked meanwhile. [ADR 0009](../adr/0009-clickable-paths.md) gives the times and limits.
  - dx runs no program to open a path and holds no list of runnable types: the herdr plugin checks the real target again at click time and alone decides what may be opened, a program included.
  - Outside herdr, off Windows, on another surface than the terminal, nothing is rewritten and the replies are drawn as Claude Code draws them.
  - `FORCE_HYPERLINK=1` is yours to set: every program the session starts inherits it.
- **Turn off**: the **Chemins cliquables** setting (settings, **Chemins**), or the herdr plugin disabled (`herdr plugin disable imsike.links`, from the next session).

## Turn off

`/plugin` > Installed > `dx` > Disable, or `claude plugin disable dx@cc-plugins`; uninstall with `claude plugin uninstall dx@cc-plugins`.

Most of what the band shows can be turned off on its own in the settings (above). The notes, and the `✎` and `⚙` icons that open the notes and settings panes, cannot: they go only with the whole plugin. Neither can the band itself, only folded (`ctrl+x ctrl+a`, or `[-]`) or turned off with the plugin. The `[ 📁 dossier .claude ]` button of the settings pane acts only when pressed: there is nothing to turn off.

Claude Code may show the tip **You haven't used the dx plugin lately. Turn it off in /plugins to save context and start faster.** It does not reflect how much dx is used: what Claude Code counts as a plugin's use is not documented, and it seems, from its behaviour, not to count the hooks of a function-hook module like dx's, so dx may never look used and the tip comes back periodically. dx brings no skill, agent or MCP server, and its hooks add nothing to the model's context: they observe and draw, and act only on the system's clipboard, written by the notes' copies, and again after a copy with the Remote Desktop repair on, and on the File Explorer, opened at a press on the settings pane's `[ 📁 dossier .claude ]` button; inside herdr, they rewrite the replies' text as the terminal draws it (the clickable paths) and run herdr's list of its plugins as the session starts (up to four more times within five minutes, should herdr fail). Its one command, `/dx-tse`, registered on Windows alone, is for you to run; whether Claude Code lists a plugin's commands to the model is not documented either. Its start costs a module load of the order of a hundred milliseconds. The tip can be ignored; `spinnerTipsEnabled: false` in the settings turns off all tips, but whether it covers this one is unconfirmed.
