# ADR 0009 — Chemins cliquables dans herdr : dx fait les liens, un plugin herdr les ouvre

- **Statut** : accepté
- **Date** : 2026-11-25

## Contexte

Les réponses de Claude nomment sans cesse des fichiers et des dossiers (`src/app.ts:12`, du code en ligne), et dans le terminal de Claude Code un chemin nu n'ouvre rien. L'API des function hooks permet à un plugin de réécrire le texte que le moteur dessine pour une réponse (`ui.render` sur `AssistantMessage`, le message enregistré intact) ; le moteur dessine un lien Markdown en hyperlien de terminal (OSC 8) là où il pense que le terminal les affiche, et écrit sinon l'URL après le texte. Il en décide comme observé dans Claude Code 2.1.330 (non documenté) : `FORCE_HYPERLINK` d'abord (vide, il compte comme non défini ; `0`, `false`, `no` ou `off`, aux espaces et à la casse près, ou un nombre lu comme 0, les désactive ; toute autre valeur les active) ; sinon Windows Terminal hors tmux (`WT_SESSION`), un `TERM_PROGRAM` de sa liste (`ghostty`, `Hyper`, `kitty`, `alacritty`, `iTerm.app`, `iTerm2`, `rex`, `WarpTerminal`), le terminal de JetBrains (`TERMINAL_EMULATOR=JetBrains-JediTerm`), tmux 3.4 ou plus récent (`TERM_PROGRAM_VERSION`), un `LC_TERMINAL` de la même liste, un `TERM` qui contient `kitty`. herdr, un multiplexeur de terminal, n'est pas connu : `FORCE_HYPERLINK=1` dans l'`env` des réglages de Claude Code les active.

L'API n'ouvre aucun fichier dans un autre programme.

herdr (0.9.5 et plus récent) envoie un ctrl+clic sur une URL à l'action d'un plugin quand un motif `[[link_handlers]]` de ce plugin la reconnaît et que la capture de la souris est active ; l'action reçoit l'URL (`HERDR_PLUGIN_CLICKED_URL`) et le panneau (`HERDR_PANE_ID`). Sans gestionnaire correspondant, herdr n'ouvre que les liens http(s). Un essai réel (herdr 0.9.5, Claude Code 2.1.330 en plein écran, Windows Terminal avec `experimental.detectURLs` désactivé) a montré un lien `[texte](dx-open:…)` dessiné en bleu avec son seul texte, survolé sur ses lignes repliées, et un ctrl+clic sur n'importe laquelle de ses lignes lançant l'action du gestionnaire en 0,2 s environ, sans fenêtre de console.

Les règles absolues n'admettent aucune dépendance d'exécution hors de Claude Code ; seul un outil fourni par le système peut être lancé par `$.process.run`, quand l'API n'offre pas d'autre moyen, avec un ADR qui dit pourquoi ([ADR 0003](0003-system-process-list.md)). herdr n'en est pas un : l'API ne peut pas dire quels plugins herdr sont installés, herdr seul le peut.

Options étudiées :

| Option | Pour | Contre |
|---|---|---|
| Rien : les chemins restent du texte | Rien à lancer | Copier un chemin pour l'ouvrir |
| Des liens `file:` dans le dessin du moteur, ouverts par le terminal | Rien à lancer | Ce qui s'ouvre est le choix du terminal (ShellExecute dans Windows Terminal : un fichier exécutable s'exécute) ; dans herdr, le seul aperçu de herdr-explorer |
| Réponses dessinées par dx, un simple clic traité par dx | Un clic, sans le terminal | L'aspect du moteur imité ; un processus par clic lancé par dx ; les contrôles des exécutables éparpillés dans dx ; Windows Terminal toujours sur le chemin |
| **Des liens `dx-open:` dans le dessin du moteur, ouverts par un plugin herdr** | L'aspect du moteur lui-même ; dx ne lance rien pour ouvrir un chemin ; l'ouverture, le choix de l'utilisateur et la protection en un seul endroit, en Rust, testé | herdr seulement ; ctrl+clic ; un second plugin à installer ; `FORCE_HYPERLINK` et le réglage de Windows Terminal à poser à la main |

## Décision

Sous Windows, dans herdr (`HERDR_PANE_ID` défini), quand le plugin herdr `imsike.links` de [Herdr-Plugins](https://github.com/IMSike/Herdr-Plugins) est installé et que Claude Code affiche les hyperliens, dx réécrit les chemins des réponses de Claude, dans le texte que le moteur dessine, en liens `[tel qu'écrit](dx-open:///C:/…/fichier#L12-L14)` :

- **une seule règle dit ce qu'est un chemin, et un mot est un chemin en entier ou pas du tout.** Le texte d'une réponse est coupé en mots à ses espaces, telles que CommonMark les lit (une espace insécable en est une, une espace sans chasse non) ; un mot collé à du code, à un lien ou à du HTML brut n'est pas un chemin. Les signes autour d'un mot qui ne sont pas du chemin sont laissés de côté : avant lui, `(`, `"`, `'` ou `<` ; après lui, `.`, `,`, `;`, `:`, `!`, `?`, `"`, `'`, `>`, et une `)` qui n'en ferme aucune ouverte dans le mot (un point après un séparateur aussi, `docs/.`, pas deux, `../..`) ; aux bords du mot, une suite de `*` ou de `_` aussi longue des deux côtés, ou `~~` des deux côtés (`**a.ts**`, `~~a.ts~~` : Claude Code ne barre qu'avec deux tildes, et dessine un tilde seul tel qu'écrit), jamais après un signe ouvrant ni de deux sortes (`"*a.ts*"`, `(**a.ts**)`, `*_a.ts_*` : contre le lien, une marque intérieure pourrait s'apparier à une autre hors du mot). Ce qui reste est un chemin quand il commence par un lecteur (`C:\`, `C:/`), le dossier personnel (`~/`), une des variables `USERPROFILE`, `LOCALAPPDATA`, `APPDATA`, `TEMP`, `TMP`, `ProgramFiles`, `ProgramFiles(x86)`, `ProgramData`, `SystemRoot`, `windir`, `PUBLIC` (`%TEMP%\`, quelle que soit la casse, lié là où elle mène), un lecteur écrit à la façon de Git Bash ou de WSL (`/c/`, `/mnt/c/`), ou est relatif ; et quand il ne contient que des lettres de toute écriture et leurs marques combinantes, des chiffres décimaux de toute écriture (ni `²` ni `½`), `. _ - + ~ @ ( ) '` et les séparateurs, autant de `(` que de `)`, jamais deux séparateurs de suite (celui de la racine compris : `/c//x`), aucun `..` au-dessus du début d'un chemin absolu (`/c/../d`), aucun nom fait de plus de deux points seuls (`src/...`), pas de barre oblique inverse finale, pas de nom court 8.3 (`PROGRA~1`), aucun nom finissant par un point ou une espace, aucun point de code ignorable par défaut, et, dans le texte, aucune barre oblique inverse devant une ponctuation ASCII (un échappement Markdown : `src\_a.ts` est dessiné `src_a.ts`). Il doit avoir l'air d'un chemin : un séparateur, ou un nom de quatre signes au moins, qui ne commence pas par un point, avec une extension qui commence par une lettre (`README.md` ; pas `1.2`, `a.h`, ni `.env` seul). Tout autre signe (`&`, `#`, `^`, `$`, `%`, `,`, `=`, `!`…) ou toute autre racine (`/tmp`, `\x`, `\\serveur`) fait du mot un non-chemin : aucune partie n'en est jamais lue comme un chemin. Un mot n'a donc qu'une lecture, vérifiée une fois sur le disque ;
- **un chemin qui contient des espaces n'est lié que là où il est délimité** : dans du code en ligne et entre guillemets doubles dans le texte (`"C:\mes notes\a.txt"`). Écrit nu, il fait plusieurs mots, et aucun n'est lié là où cela se voit : de deux mots séparés seulement par des espaces, le second non absolu, aucun n'est lié quand l'autre contient un signe que contient un nom en plus des lettres et des chiffres (`C:\mes notes\a.txt`, `fichier (1).txt`, `a - copie.md`). Un mot qui finit par des signes laissés de côté, ou une fin de ligne, termine le chemin (`src/a.ts, src/b.ts` est une liste, comme des chemins un par ligne). Un mot entre blancs dont Claude Code fait un lien dans le texte, qui contient `://` ou `www.` n'importe où, ou une adresse e-mail (`a@b.com`), ne contient aucun chemin, ni rien de collé à lui, code en ligne compris : Claude Code étend une telle URL sur tout ce qui est collé après elle ;
- les chemins sont aussi lus dans le code en ligne, tels qu'écrits (pas d'échappement là ; une espace retirée de chaque côté quand les deux en ont une, comme le fait CommonMark) ; les URL `file:`, l'encodage en pourcentage et les références de caractères ne sont pas lus. Une ligne ou une plage va avec le lien : `:12`, `:12-14` ou `:12:5` (la colonne laissée) après un chemin dans le texte ou le code. Le Markdown de la réponse est lu comme CommonMark 0.31.2 le lit (`markdown.ts`) : le code sous toutes ses formes, le HTML brut, les liens automatiques, les liens (leur texte et leur cible), les images et les définitions de références restent tels qu'écrits. Claude Code lit les réponses avec son propre analyseur, bâti sur marked dont il remplace bien des règles ; dx modélise CommonMark 0.31.2, avec le barré et les liens automatiques de GFM, comme une approximation de celui-ci, vérifiée contre l'analyseur de Claude Code 2.1.332 sur des réponses réelles et sur des réponses tirées au hasard, les différences restantes listées dans les conséquences ;
- un chemin n'est lié que s'il existe (`$.fs.stat`, gardé 5 minutes, 10 s quand il est absent ; un dessin attend 0,3 s au plus ses vérifications, une vérification en retard attendue par aucun dessin suivant, et faisant redessiner les réponses quand elle répond ; une vérification sans réponse jamais redemandée avant qu'elle réponde, un lecteur mort pouvant ne jamais répondre), si, tel qu'écrit une fois une variable remplacée et là où il aboutit (`realPath`), le plugin herdr le prend (un lecteur, moins de 260 unités UTF-16, aucun nom de périphérique comme `con.txt`) et la règle propre de dx, plus stricte, aussi (des noms faits des seuls signes ci-dessus ou d'espaces, aucun finissant par un point ou une espace : herdr en refuse moins : `/ \ : * ? " < > | , ; %`, les caractères de contrôle, invisibles et à usage privé, les non-caractères), s'il n'est pas trop large en texte ou en code (la racine d'un lecteur, le répertoire de travail, le dossier personnel), et s'il n'est pas un des fichiers de réglages de Claude Code lui-même, tel qu'écrit ou là où il aboutit (`realPath` ; un chemin dont le moteur ne dit pas où il aboutit n'est pas lié), ni un de ceux du dossier où aboutit le dossier de configuration de Claude Code. Au plus 256 chemins distincts par réponse, et aucun lien dont l'URL dépasserait 2 048 caractères ; aucun dans une réponse de plus de 100 000 caractères ou 1 000 lignes, que Claude Code dessine sans hyperliens (lu dans Claude Code 2.1.330, non documenté) ;
- un lien posé par dx ne change rien d'autre à ce que CommonMark lit de la réponse : après un `!` non échappé, il l'échappe ; un chemin qui contient un `_` ou un `~~` qui peut s'apparier à un autre, selon les règles d'encadrement de CommonMark, n'est pas lié, entre guillemets aussi : dessiné en emphase, il n'est pas ce qui est écrit (`__init__.py`, `src/_a_.ts`), et un lien casserait l'emphase (`_voir le src/a.ts_`, `_voir "src/b_"`) ; rien n'est lié là où un lien ferait une autre référence (`[ref][src/a.ts]`). L'URL ne porte que le chemin et les lignes : `dx-open:///` puis le lecteur et chaque segment encodé en pourcentage en UTF-8 (parenthèses, `!`, `'` et `*` compris), puis `#L12` ou `#L12-L14`. Ce que fait un clic, et si un fichier exécutable peut jamais être lancé, est le réglage du plugin herdr, jamais lu dans l'URL ; ce plugin vérifie de nouveau la vraie cible au moment du clic ([ADR 0012 de Herdr-Plugins](https://github.com/IMSike/Herdr-Plugins/blob/main/docs/fr/adr/0012-link-dispatch.md)).

La grammaire est étroite à dessein : un chemin lu aussi loin que le texte le permet (au-delà de ses espaces, avec ou sans marques d'emphase), la plus longue lecture qui existe liée, laisserait un signe collé à un chemin faire d'une de ses lectures le nom d'un autre fichier. Un mot entier lu une seule fois ne laisse aucune lecture plus courte qui puisse se tromper. Elle est tenue par un juge, `paths-oracle.test.tsx` : des réponses tirées au hasard dont le sens de chaque élément est connu, un disque qui contient le chemin voulu et des leurres (chaque partie d'un élément coupé à un signe), chaque lien vérifié pour mener à un chemin que son élément veut dire, et un cinquième au moins des chemins voulus liés ; les constats des audits y restent comme cas fixes.

dx lance un processus au démarrage de la session, seulement dans herdr : `herdr plugin list --plugin imsike.links --json`, la liste en lecture seule de herdr (herdr par le chemin que herdr donne à ses panneaux dans `HERDR_BIN_PATH` quand c'est un chemin absolu avec un lecteur, sinon `herdr` par son nom, trouvé dans le `PATH` ; lancé depuis le dossier du système (`SystemRoot`, sinon `windir`) pour qu'aucun `herdr.exe` du répertoire de travail ne soit lancé à sa place, et pas lancé du tout quand aucun des deux n'est défini ; 10 s au plus, redemandée si elle échoue ou tarde, après des pauses de 5 s, 30 s, 1 min et 2 min, chacune tirée à 10 % près dans un sens ou l'autre pour que les sessions que herdr restaure ensemble ne la demandent pas ensemble), que le démarrage de la session n'attend pas. herdr est l'outil tiers, détecté à l'exécution, dont l'absence ne change rien : la règle 5 d'[AGENTS.md](../../../AGENTS.md) et le guide de contribution admettent un tel outil à partir de cet ADR, chaque nouvel usage avec son propre ADR. Le plugin listé, activé et doté de son gestionnaire `dx-open` active les liens ; tout autre cas laisse les réponses telles que le moteur les dessine, pour qu'aucun lien ne mène nulle part.

L'onglet **Fonctions** du panneau des réglages montre, dans herdr seulement, une section **Chemins** : **Chemins cliquables** (activé par défaut), et une ligne qui dit ce qui manque : le plugin herdr, herdr qui ne répond pas, le dossier du système inconnu, ou `FORCE_HYPERLINK=1` (dit à part quand `FORCE_HYPERLINK` est défini pour désactiver les hyperliens).

## Conséquences

- dx ne lance rien pour ouvrir un chemin et ne tient aucune liste de types exécutables : le plugin herdr est le seul endroit qui ouvre, et qui refuse.
- Ce que la grammaire étroite laisse sans lien, à dessein : un chemin qui contient des espaces écrit nu ; un chemin collé à un signe hors de la liste (`src/a.ts#L5`, `100%.txt`, `Q&A/x.md`), ou voisin d'un mot qui contient un des signes d'un nom (`src/a.ts (1.2)`) ; un chemin depuis une racine (`/tmp/x`, `/etc/hosts`) ; les autres montages de Git Bash ; un chemin qui contient `www.` (`docs/www.readme.md`, une adresse web pour Claude Code) ; un chemin dans un lien que le modèle écrit. Un mot fait de lettres seules à côté d'un chemin est pris pour de la prose : `C:\Program Files` écrit nu lie `C:\Program` quand celui-ci existe, et `C:\x\mes vieilles notes\a.txt` lie `C:\x\mes` et `notes\a.txt`, relatif au répertoire de travail, quand ils existent.
- Là où l'analyseur de Claude Code lit une réponse autrement que le modèle de dx, dans de rares réponses :
  - Claude Code dessine chaque lien de la réponse en `texte (adresse)`, et un chemin lié s'affiche `src/a.ts (dx-open:///C:/…)`, quand une balise HTML en ligne est laissée ouverte plus tôt dans la réponse (`<code>`, `<kbd>`, `<pre>`, `<script>`, `<a …>`), quand la réponse contient un `\r` (fins de ligne CRLF), ou quand elle finit par exactement une espace après un élément de liste, une case à cocher ou un soulignement de titre setext, sans saut de ligne final.
  - Une réponse qui ne contient aucun signe Markdown est dessinée telle quelle, sans être analysée ; dès que dx y ajoute un lien, elle l'est, si bien que `a\.b` s'affiche `a.b` et que `1.<tab>foo` devient une liste. Le chemin reste cliquable.
  - Un chemin après une tabulation qui suit une marque de liste ou de citation (`1. <tab>src/a.ts`) est du code indenté pour Claude Code : le lien s'affiche brut.
  - Un `~` juste avant des accents graves (`` ~`src/a.ts` ``) fait lire ceux-ci à Claude Code comme du texte, pas comme du code en ligne : un chemin lié là s'affiche sans ses accents graves, ou son lien brut.
- Hors de herdr, hors de Windows, sans le plugin ou sans hyperliens, les réponses sont dessinées intactes ; le coût est la lecture de quelques variables d'environnement, et dans herdr un processus par session (jusqu'à cinq tant que herdr échoue ou tarde).
- Le plugin installé pendant une session prend effet à la session suivante.
- L'aspect des réponses est celui du moteur ; le message enregistré, et ce que le modèle relit, ne changent pas.
- `FORCE_HYPERLINK=1` est à poser par l'utilisateur (dx ne le pose pas : chaque programme lancé par la session en hériterait) ; `experimental.detectURLs` désactivé dans Windows Terminal et la capture de la souris de herdr active sont documentés, pas vérifiés.
- Un modèle, ou un programme d'un autre panneau, qui écrit un lien `dx-open:` ne peut faire faire au plugin que ce qu'un vrai lien fait avec le propre réglage de l'utilisateur ; dx laisse un tel lien du modèle tel qu'écrit, et le plugin herdr est le garde-fou.
- dx laisse telles quelles les URL `file:` écrites par le modèle : avec `experimental.detectURLs` désactivé dans Windows Terminal et la souris capturée par herdr, rien ne les confie à Windows, et hors de herdr ce qu'un terminal en fait est son propre comportement, pas celui de dx. Réactiver la détection des URL de Windows Terminal ramène ce risque : un ctrl+clic sur une telle URL peut alors lancer un programme.
- Les fichiers de réglages de Claude Code lui-même restent sans lien : Claude Code refuse qu'un plugin les nomme à un programme, et dx ne contourne pas ce refus par un autre programme ; le bouton `[ 📁 dossier .claude ]` du panneau des réglages ouvre leur dossier ([ADR 0007](0007-configuration-folder.md)).
- Forme des réglages `settings-14` : un booléen ajouté ; une nouvelle clé d'état `paths` (forme `paths-1`), ce que le panneau des réglages dit des prérequis.
- À réévaluer si l'API ouvre elle-même les fichiers, si Claude Code documente ou change sa règle des hyperliens, ou si herdr change ses gestionnaires de liens.
